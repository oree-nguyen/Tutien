# H01 source-graph garment experiment

Run from the repository root with the locked Node dependencies installed and the NumPy/SciPy/PyAMG environment in `requirements-surface.txt`. Outputs are isolated under `.local/rig-candidates/`; no command below activates a candidate or overwrites a canonical model. The original source GLB, rig, hand frames, tools and pose data are tracked inputs.

The existing cloud Python already supplies pinned NumPy/SciPy. PyAMG5.3.0 was installed and exercised in a local target; future setup can install the complete pinned file in a writable virtual environment. To use the same local-target arrangement:

```bash
python3 -m pip install --target .local/rig-python --no-deps pyamg==5.3.0
export PYTHONPATH=.local/rig-python
```

The exporter now defaults to the tracked canonical rig. It reconstructs its hand protection mask from that exact rig, the tracked hand-frame bounds, all finger-influenced vertices and one original triangle-edge ring. The input/source/hand-frame/mask SHA values are saved together; a mask from an unrelated local experiment is never reused silently.

```bash
node tools/rig/semantic-h01-garment.mjs --input assets/rigged/H01-C0-rigged.glb --output .local/rig-candidates/semantic-garment
OPENBLAS_NUM_THREADS=1 python3 tools/rig/audit-semantic-garment.py .local/rig-candidates/semantic-garment
RIG_FILE=.local/rig-candidates/semantic-garment/H01-C0-rigged.glb REFERENCE_POSE=docs/anim-report/harmonic-held/H01-reference-idle-solve.json RIG_REPORT_FILE=docs/anim-report/semantic-garment/held-all-mesh.json node tools/rig/validate-all-meshes.mjs
node tools/rig/preview-semantic-garment.mjs
```

The first command rebuilds using the chosen parent; changing the parent is a new experiment and must produce a fresh receipt and fresh checks. An explicit `--source` is supported, but every oriented source triangle and original position/normal/UV array must match. Multi-primitive input is rejected rather than silently processing the first mesh.

The conver10 initial/v2/v3 comparisons instead used the previously prepared harmonic-projected parent, SHA `b51ff99d4371eba5bb535039524d6328c20da746e45ff9d08ba17119214c3a1c`. That parent is generated by this historical chain:

```bash

node tools/rig/harmonic-body.mjs
SKIN_FIT_ITERATIONS=300 node tools/rig/optimize-surface.mjs
SKIN_FIT_ITERATIONS=500 node tools/rig/optimize-surface.mjs --projected
node tools/rig/semantic-h01-garment.mjs --input .local/rig-candidates/harmonic-projected/H01-C0-rigged.glb --expected-parent-sha b51ff99d4371eba5bb535039524d6328c20da746e45ff9d08ba17119214c3a1c --output .local/rig-candidates/semantic-garment-v3
```

The historical intermediate SHA chain is source `292c2631…` → reference `e23c6f1f…` → harmonic `c05a0b42…` → global `fee679ce…` → projected `b51ff99d…`. The long historical chain was not rerun in this correction; the existing hash-checked parent was used. The final command's full SHA check prevents silently substituting a different generated parent. These historical optimizers remain rejected diagnostics and are not prerequisites for a fresh run from the tracked canonical rig.

`--reuse-solve` only re-exports existing solve arrays after checking the exact source/parent SHA and regenerating/comparing the protected-mask SHA. It does not rerun or claim new numerical convergence. Source triangle and UV-boundary sidecars are generated with the candidate and validated by `validate-all-meshes.mjs`; no large failed GLB or disposable raw arrays need to be committed.

The v4 semantic-only correction adds original source-face patches recovered from exact cuff ray picks. Patches are tied to the original source SHA and their binary face-map SHA/count; conflicting or stale patches reject. Their source corners become hard semantic seeds on the original edge graph, removing competing lower-robe seeds, and every listed source face retains its specified sleeve label. This changes semantic ownership only. `--reuse-supports-from` validates source/parent/protection/geometry arrays and the prior receipt-bound GLB before reusing its exact source joint IDs and weights:

```bash
node tools/rig/semantic-h01-garment.mjs --input .local/rig-candidates/harmonic-projected/H01-C0-rigged.glb --expected-parent-sha b51ff99d4371eba5bb535039524d6328c20da746e45ff9d08ba17119214c3a1c --output .local/rig-candidates/semantic-garment-v4 --seed-patches docs/anim-report/semantic-garment-cuff-review/source-cuff-patches.json --reuse-supports-from .local/rig-candidates/semantic-garment-v3
```

The source patches remain provisional clothing-pattern evidence. Front/side/back sleeve and two-panel isolates show that the gold cuff tails move out of the lower-robe labels, but the lower-robe labels still contain multiple layers/components and rough albedo-derived borders. No cut is treated as a free seam, and every original face remains present.

The v5 solve fixes a specific homogeneous-field error: a joint with an identically zero boundary/target RHS must solve as zero. Retaining its arbitrary initial weights caused a discontinuous Spine1 field near the torso target boundary. The corrected solver initializes all fields to zero and uses prior weights only as the active joint's CG initial guess. The zero-RHS regression runs without PyAMG. Rebuild v5 with the preceding command, changing `--output` to `.local/rig-candidates/semantic-garment-v5` and omitting `--reuse-supports-from`.

For the held pose, original unique source-edge maxima decreased from v3/v4 **23.6357** to v5 **13.3592**; the dense pre-reduction fields decreased from **15.3660** to **6.6805**. These remain rejected. The remaining largest reduced-field edge is source vertices **754901/754903**, near the right sleeve/robe transition; the reduction magnifies an already excessive dense support gradient. This is not evidence that more linear-solver iterations can repair it, or that the source garment is globally impossible. The independently recorded wrist-to-waist path witness requires at most **1.7434** on its sampled endpoints and does not establish whole-garment feasibility.

The v6 comparison replaces the inverse-edge-length graph/global-median screening approximation with a cotangent surface FEM stiffness and lumped original-source triangle-area mass. The screened system is `Lcot + M/r²` on the target patches, with existing cuff/hand/domain boundaries fixed. `Lcot` is dimensionless and `M` has square-metre units. The earlier graph used `median(edgeLength)/r²`, so it had approximately correct units on uniform meshes; the problem being tested is its irregular-resolution and anisotropy dependence, not an asserted universal millimetre smoothing radius.

```bash
SCREENING_SCALE_REPORT=docs/anim-report/semantic-garment-v6/screening-scale-fixture.json OPENBLAS_NUM_THREADS=1 python3 -m unittest discover -s tools/rig -p test_source_garment_graph.py
PYTHONPATH=.local/rig-python node tools/rig/semantic-h01-garment.mjs --input .local/rig-candidates/harmonic-projected/H01-C0-rigged.glb --expected-parent-sha b51ff99d4371eba5bb535039524d6328c20da746e45ff9d08ba17119214c3a1c --output .local/rig-candidates/semantic-garment-v6 --seed-patches docs/anim-report/semantic-garment-cuff-review/source-cuff-patches.json --support-operator cotangent-fem
```

The 8 cm planar-strip fixture compares the same world positions against the analytic screened-step profile: coarse/refined FEM maximum difference **0.000357**, locally refined FEM maximum analytic error **0.000387**, earlier global-median graph error **0.146868** on that locally refined strip. This verifies discretization behavior only; actual garment deformation must be measured separately.

The first unconstrained FEM attempt rejected export because obtuse source triangles produced ten negative support entries, minimum **−0.009119**. Its failure remains in `docs/anim-report/semantic-garment-v6/unconstrained-fem-rejection.json`. A bounded per-bone convex FEM energy solve now fixes violated zero bounds and checks free residual plus primal/dual KKT conditions at each active-set step. It does not silently clip those invalid supports. KKT applies to each bone field **before** partition normalization and four-influence sparsification; these independent field solves are not a coupled simplex optimum. Exported-mesh gates remain authoritative.

Segmentation uses albedo as seed evidence on the original edge graph. The source topology audit lists every component and saves exact SHA-bound source-face seed patches. These proposed labels do not establish an accepted clothing pattern or anatomical body segmentation. The source weld map includes only unique paired opposite original UV-boundary halfedges; it never stitches nearby unrelated layers.

Four-influence reduction subtracts the fifth ranked influence before normalization, so an exchanged support goes continuously to zero. Equal-top-five singularities reject export. The focused regression command is:

```bash
OPENBLAS_NUM_THREADS=1 python3 -m unittest discover -s tools/rig -p test_source_garment_graph.py
```

Every exported revision requires bind, upright, intermediate and full-animation measurements on every primitive, 1 µm source-copy continuity, garment boundary review, area/cross-section/collision checks and exact grip validation. Conver10 revisions are staging experiments until all relevant gates pass. A converged linear solve or preserved texture never authorizes activation.
